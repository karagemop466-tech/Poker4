Method, source table and repo findings

How every number on this site was obtained, what was checked against what, and the irregularities found in the repository itself.

The verification protocol, applied to every row

  1. Read the operator's own page or PDF. Not an aggregator, not a search snippet, not a review site.
  2. Record the retrieval date and a verbatim excerpt for the value. Those live in data/v2/sources.json and are visible on every table row's source link.
  3. Cross-check the second source. The Venetian calendar gives the buy-in and guarantee; that row's structure sheet gives the chips, level minutes, late-registration clock, house fee and pool contribution. Where they disagree, both are shown and the row is flagged.
  4. Never infer a rule from silence. A missing re-entry sentence is not a freezeout. The site proves this by citing prior-season Venetian sheets that print re-entry when they mean it.
  5. Leave it blank rather than estimate. A blank is rendered UNVERIFIED and appears on Flagged for review.

Repo review — irregularities found in this repository

R1Residual merge-conflict markers in COORDINATION.md. A ======= line and a >>>>>>> origin/main line survived a merged PR, with a duplicated session block between them.Removed the two delimiter lines only; both blocks of text were kept verbatim. Logged in COORDINATION.md.
R2Several parallel sites ship competing “single entry” claims. strip/, verified/, df41f5c6/, c07371e3/, 60fb62da/ and pages/ each carry their own snapshot; some earlier dashboards showed “single-entry” labels that were later corrected.This version does not edit or delete them; it links them as historical snapshots from index.html and states the current rule (zero confirmed Venetian single-entry rows).
R3No data is shared between the parallel sites. Six separate JSON schemas, four separate build scripts.The new data/v2/ layer plus tools/v2_*.py is self-contained and documented here so the next session can extend it rather than fork it again.
R4Bellagio Saturday structure sheet contradicts itself — filename says $1,000, heading says $1,100, rule 07 splits a $600 buy-in.Flagged, buy-in not asserted; both figures shown on the row.
R5Guarantee semantics were mixed in earlier snapshots. Venetian prints “$8,000 (prize pool + total bounties)” — not a pure pool guarantee.Every guarantee on this site carries a guarantee_basis of prize_pool or pool_plus_bounties, and the ratio column tags the bounty-inclusive ones.
R6Caesars flyer is undated for a specific calendar day and carries no day-of-week qualifier.Rows are marked “daily, recurring”, not given dates.
R7Walking times were previously absent or unlabelled.Now computed with a documented method (OSRM foot routing, property centroids) and labelled as an estimate on every row and in the footer.

How to reproduce this snapshot

python3 tools/v2_extract.py        # Venetian 94 rows + structure facts  -> data/v2/events.json

python3 tools/v2_verify.py          # link + source + blank audits

Files are plain HTML/CSS/JS with no build step at deploy time; GitHub Pages serves the repository root, so v2/ is live as soon as it is on main.

How to read this site. A value is shown only if a session runner read it on the official page linked in that row, on 2026-11-17. Everything else says UNVERIFIED and appears on the Flagged for review page with its source links.
