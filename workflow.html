Decision workflow

The staged process this dashboard is built to support — work top to bottom; do not skip the confirmations.

  1. Fix trip dates and a nightly budget/quality floor. Without dates, hotel totals are not comparable. Use the trip calculator to set the envelope.
  2. For candidate events, obtain the official structure sheet and written maximum-entry / no-rebuy / no-add-on rules. Remove any event that does not match the single-entry policy. In this snapshot, that filter removes everything — the public sheets state re-entry/rebuy/add-on or say nothing (see entry-rule excerpts).
  3. Compare only surviving events on guaranteed pool, buy-in, starting stack / blind duration, payout structure, and daily schedule fit. The ranking tables do the arithmetic; the columns carry the caveats.
  4. Obtain itemized hotel totals for the same stay (checkout total, nightly average, resort fee, tax, parking, cancellation deadline, rate timestamp) and record them in the rate log. Check the walking route under 30 minutes (walk filter).
  5. Build one event per day first. Add evening events only where you can realistically exit the earlier event — the day plan marks these as conditional fallbacks and flags impossible sequences.
  6. Reconfirm official schedules, rates and policies before any nonrefundable payment. The change monitor shows what moved since the last check.

Standing rules used throughout

  • Ranking happens only after total entry fee and guarantee are confirmed; the ratio is descriptive, never a forecast.
  • Bounty, satellite/seat, and multi-flight events are labeled and ranked separately.
  • Rates are kept as a dated log, never a single overwritten value.
  • Blank + flagged beats inferred. Every row links an official source or is marked unverified.
